# RFC-0001: Niezależność standardu od technologii

**Status:** Proposed · **Wersja:** 0.1

## Kontekst

Ekosystem Nasza Sprawa ma umożliwiać różnym społecznościom, organizacjom i instytucjom współdziałanie przy rozpoznawaniu potrzeb i realizacji działań. Nie każdy uczestnik korzysta z Internetu, a organizacje mogą wybierać różne narzędzia. Dlatego technologia nie może definiować samej metodyki.

## Proponowana decyzja

1. Standard podstawowy definiuje znaczenia pojęć, role, minimalny przebieg procesu, obowiązkowe ślady decyzji oraz reguły weryfikacji.
2. Standard podstawowy musi być wykonalny w całości na papierze.
3. Implementacje cyfrowe mogą dostarczać dodatkowe profile API, zdarzeń, importu/eksportu, federacji i rozszerzeń.
4. **Nasza Sprawa** jest planowaną implementacją cyfrową. **MSTU** to planowany pierwszy dostawca tożsamości, ale ani aplikacja, ani MSTU nie są wymagane do stosowania podstawowego standardu.
5. Instytucje publiczne są pełnoprawnymi współtwórcami, ale współpraca nie zastępuje ich formalnych kompetencji.
6. Zgodność proceduralną można ocenić bez komputera; zgodność API jest osobnym, opcjonalnym profilem.

## Konsekwencje

**Zyskujemy:** dostępność, trwałość, niezależne implementacje, możliwość migracji i lokalne dostosowania.

**Koszty:** potrzeba dobrej dokumentacji, szczegółowego modelu znaczeń oraz mechanizmu wyjaśniania różnic między procesami.

## Otwarte pytania

Jak publikować normatywne wersje standardu? Jak testować ręczne procesy? Jak pogodzić lokalne modyfikacje ze zgodnością? Jak zarządzać zmianami i zgodnością wsteczną? Kto może potwierdzać zgodność?

## Stan

Dokument do konsultacji. Nie oznacza przyjęcia standardu przez jakąkolwiek instytucję.
