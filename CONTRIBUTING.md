# Jak współtworzyć standard?

Zapraszamy mieszkańców, przedstawicieli administracji, organizacji pozarządowych, przedsiębiorców, edukatorów, wolontariuszy i programistów.

Nie trzeba umieć programować. Wkładem może być pytanie, obserwacja, przykład problemu, propozycja formularza, test pilotażu, przegląd czytelności lub zmiana specyfikacji.

## Proponowany tryb pracy

1. Zgłoś potrzebę lub niejasność — w GitHub Issues albo podczas konsultacji analogowych, gdy zostaną uruchomione.
2. Opisz problem w języku zrozumiałym dla osoby spoza branży IT.
3. W przypadku zmian normatywnych utwórz RFC lub opisz propozycję, aby ktoś pomógł ją zapisać.
4. Dyskutujemy jawnie, z szacunkiem; wskazujemy konsekwencje dla mieszkańców, urzędów i realizatorów.
5. Testujemy ważne zmiany zarówno na przykładach papierowych, jak i — w przyszłości — cyfrowych.
6. Każda decyzja o przyjęciu lub odrzuceniu ma uzasadnienie.

## Reguły zmian

- Nie narzucaj technologii w standardzie podstawowym.
- Nie wpisuj do publicznych Issues danych osobowych osób trzecich ani poufnych spraw urzędowych.
- Nie obiecuj realizacji działań w imieniu organizacji, do której nie masz umocowania.
- Proponowane zmiany procedur administracyjnych muszą być zweryfikowane z punktu widzenia obowiązujących przepisów.
- Zachowujemy miejsce na lokalne implementacje i różne modele organizacyjne.
- Do czasu formalnego przyjęcia licencji nie zakładaj, że wkład jest automatycznie udostępniany na CC BY 4.0; zasady licencyjne są przedmiotem konsultacji.

## Głosy spoza GitHuba

GitHub służy do współpracy nad dokumentacją, ale nie może być jedynym kanałem konsultacji. Propozycje z rozmów, zebrań i formularzy papierowych mogą być wpisywane przez upoważnionego pośrednika, z zaznaczeniem źródła i po usunięciu danych nieprzeznaczonych do publikacji.
