# Materiały prezentacyjne z weryfikacji
Uzgodniona zasada: wyniki weryfikacji i testów wykorzystamy w przyszłej prezentacji standardu, pokazując problemy, luki, sposób ich zaadresowania i dowody. Nie deklarować skuteczności przed wykonaniem testów.
## Szablon karty prezentacyjnej
- ID studium przypadku, testu, luki i wymagania; wersja standardu.
- Sytuacja wyjściowa i klasyfikacja: hipotetyczna, zgłoszona, udokumentowana, pilotaż.
- Problem i wariant negatywny.
- Zachowanie przed poprawką / wykryta luka.
- Proponowane rozwiązanie i uzasadnienie, także gdy nie wymaga zmiany standardu.
- Korzyść oczekiwana dla uczestników i koszt proceduralny.
- Status: wykryta / propozycja / zaakceptowana / wdrożona w specyfikacji / zweryfikowana praktycznie; odnośniki do dowodów.
- Porównanie papier/e-mail/aplikacja, gdy adekwatne.
- Prywatność i anonimizacja; bez niepotwierdzonych zarzutów.

## Proces
Każda kolejna partia weryfikacji powinna zawierać materiał problem → luka → odpowiedź → oczekiwana korzyść → status/dowód. Po konsolidacji uzupełnić odnośniki do przyjętych wymagań, po pilotażu rzeczywiste wyniki i ograniczenia. Zachować również przypadki niepowodzeń i odrzucone poprawki. Prezentacja publiczna ma wyjaśniać ewolucję standardu, a nie sugerować, że hipotetyczne przypadki są wdrożeniami.
